# NEXORA Android

**Native Android management platform — Non-root first, Hybrid Access.**

NEXORA is an Android-native project scaffold built with Kotlin, Jetpack Compose, Material 3, and a modular architecture. Its access strategy is **Standard + ADB + Shizuku**, without requiring root.

> **Project status:** Foundation scaffold. This repository establishes the build, module boundaries, initial UI, documentation, and safety contracts. It is not a claim that every planned device-management operation is already implemented. Each feature must be implemented and verified on real devices before being marked complete.

## Requirements

- Android Studio with a compatible Android SDK
- JDK 17
- Android SDK Platform 35
- Gradle 8.11.1 or compatible wrapper generated by Android Studio
- Internet access for the first dependency resolution

## Open and build

1. Extract the ZIP.
2. Open the `nexora-android` directory in Android Studio.
3. Allow Gradle sync and install Android SDK Platform 35 if prompted.
4. Run the `app` configuration on an emulator or physical Android device.

If using a terminal with Gradle installed:

```bash
gradle assembleDebug
gradle test
gradle lint
```

To generate a Gradle wrapper in this directory:

```bash
gradle wrapper --gradle-version 8.11.1
```

Then use `./gradlew` (Linux/macOS) or `gradlew.bat` (Windows).

- Standard / ADB / Shizuku provider boundaries
- Documentation, feature matrix, security policy, and CI workflow

## Planned access modes

| Mode | Intended role | Important limitation |
|---|---|---|
| Standard | Public Android SDK APIs | Restricted by Android permissions and package visibility |
| ADB | Operations available to an authorized shell identity | Wireless debugging being enabled does not automatically give an app an ADB shell |
| Shizuku | Binder access through the Shizuku server identity | Actual permissions depend on server mode, Android version, and OEM |

No provider is allowed to claim an operation succeeded until the result is verified.

## Safety principles

- No root requirement and no root-based implementation target.
- No arbitrary command execution from UI code.
- Validate access and capabilities before each operation.
- Risk-classify shell commands and deny destructive patterns.
- Keep operation logs free of secrets.
- Treat plugins as untrusted input.
- Use least privilege and explicit user confirmation.
- Show `AVAILABLE`, `LIMITED`, `UNAVAILABLE`, or `PERMISSION_REQUIRED` honestly.
